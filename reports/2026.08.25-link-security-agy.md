### 1. Critical: Silent Overwrite and Destruction of Reader's Annotations via Undo

- **Citations:** [L106–118](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L106-L118) (`undo`), [L145–155](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L145-L155) (`store`), [L1218–1227](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L1218-L1227) (`backToMine`)
- **Failure Scenario:**
  1. A reader has 15 personal annotations saved in `localStorage['jem-annotations-v1']`.
  2. The reader opens a shared link (`fromUrl`), which sets `fromLink = true` and saves their personal annotations into `shadowed`.
  3. The reader clicks "Back to my 15 annotations" (`backToMine()`). This function snapshots the shared annotations into `undoStack`, restores the user's features, removes `ANN_STORE_SHARED`, sets `fromLink = false`, and tells the user: *"The shared set is in Undo if you want it."*
  4. The reader presses Undo (`undo()`).
  5. `undo()` pops the shared set into `feats` and invokes `changed(true)`.
  6. `changed()` calls `store()`. Because `fromLink` was set to `false` in step 3, `store()` writes `feats` (the shared set) directly into `ANN_STORE` (`jem-annotations-v1`).
  7. The reader's original personal annotations in `localStorage` are completely overwritten by the shared set with no confirmation. On next visit or page reload, their original work is permanently gone.
- **Static Site Mitigation:**
  Include the active storage target / `fromLink` state inside the undo snapshot object (`{ f: feats, s: sourceName, fromLink: fromLink }`). When restoring a state in `undo()`, restore `fromLink` accordingly so popping back to a shared set never targets the reader's primary `ANN_STORE`.

### 2. Critical: Session Trap & Work Loss When Editing a Shared Link Without Prior Annotations

- **Citations:** [L95](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L95) (`var fromLink`), [L147](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L147) (`store`), [L1204](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L1204) (`fromUrl`), [L1218–1227](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L1218-L1227) (`backToMine`), [L1228–1243](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L1228-L1243) (`offerRestore`)
- **Failure Scenario:**
  1. A reader with a clean browser (no existing annotations in `localStorage`) opens a shared `?ann=` link.
  2. `fromUrl()` runs: `fromLink = true; shadowed = restore();` (which evaluates to `null`).
  3. The reader clicks the pencil icon (`#ann-edit`) to unlock editing, deletes unwanted features, and draws 10 new annotations for their own study project.
  4. Every auto-save calls `store()`. Because `fromLink === true`, all work is saved exclusively to `ANN_STORE_SHARED` (`jem-annotations-shared-v1`).
  5. Because `shadowed` was `null`, the `#ann-mine` button is hidden, so `backToMine()` is unreachable. `fromLink` is never reset to `false`.
  6. The reader closes the browser tab.
  7. The next day, the reader opens the site at its base URL (without `?ann=`).
  8. `open()` calls `offerRestore()`, which queries only `ANN_STORE` (`jem-annotations-v1`). It finds nothing.
  9. The map displays completely empty. The user's work remains stranded in `ANN_STORE_SHARED` and will be permanently overwritten the next time they open any other shared link.
- **Static Site Mitigation:**
  When a user unlocks a shared set (`setLocked(false)`) or creates/edits marks while `shadowed === null`, promote the session to a personal session by flipping `fromLink = false` and persisting to `ANN_STORE`.

### 3. High: Decompression Bomb & Unbounded Memory Allocation in `unpack()`

- **Citations:** [L763–780](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L763-L780) (`loadText`), [L795](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L795) (`loadFile`), [L837–848](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L837-L848) (`unpack`), [L1198–1216](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L1198-L1216) (`fromUrl`)
- **Failure Scenario:**
  1. An attacker crafts a raw deflate payload of ~4 KB containing nested whitespace or repetitive JSON structure that decompresses to 500 MB+.
  2. The attacker shares `https://example.com/map/?ann=z<payload>`.
  3. A victim opens the link. `unpack()` executes:
     `new Response(new Blob([bytes]).stream().pipeThrough(new DecompressionStream('deflate-raw'))).text()`
  4. Unlike `loadFile()` which validates `file.size > ANN_MAX_BYTES` (6 MB) upfront ([L795](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L795)), `unpack()` buffers the entire decompressed stream into a JavaScript string with zero streaming length checks.
  5. The browser tab freezes from massive heap allocation and crashes due to OOM (Out Of Memory) before `loadText()` or `problemWith()` is ever reached.
- **Static Site Mitigation:**
  Read the `DecompressionStream` via a streaming reader chunk-by-chunk with a byte counter. If cumulative decoded bytes exceed `ANN_MAX_BYTES` (6 MB), call `reader.cancel()` and reject the promise immediately. In addition, check `text.length > ANN_MAX_BYTES` at the top of `loadText()`.

### 4. High: Polygon Coordinate Aliasing Causes 2× Coordinate Drift on Drag

- **Citations:** [L598–605](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L598-L605) (`finish`), [L620–631](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L620-L631) (`shiftGeom`), [L642–646](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L642-L646) (`drag`)
- **Failure Scenario:**
  1. A reader draws a polygon and clicks "Finish".
  2. [L602](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L602) creates the closed polygon geometry using `pts.concat([pts[0]])`. This places the identical array reference of vertex 0 at both index `0` and index `ring.length - 1` (`coordinates[0][0] === coordinates[0][last]`).
  3. The reader grabs the body of the polygon and drags it to move the whole shape (`dragging.whole === true`).
  4. `shiftGeom()` iterates through every point in `coordinates` using `c.forEach(walk)`.
  5. At index 0, `walk` modifies `pts[0]`: `c[0] += dlon; c[1] += dlat`.
  6. At the final index, `walk` encounters `pts[0]` again (same object reference) and applies `c[0] += dlon; c[1] += dlat` a second time.
  7. Vertex 0 moves across the map at twice the speed of all other vertices, causing the polygon to distort and tear apart during dragging.
- **Static Site Mitigation:**
  Clone the point object when closing the ring in `finish()`: `pts.concat([pts[0].slice()])`.

### 5. Medium: Phishing, Map Defacement, and Unbounded String Injection via Shared Links

- **Citations:** [L345–389](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L345-L389) (`redraw`), [L554](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L554) (`hover`), [L587](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L587) (`showCard`), [L739–756](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L739-L756) (`adopt`)
- **Failure Scenario:**
  1. An attacker constructs a GeoJSON link containing annotations that overlay official map boundaries with falsified geopolitical borders or military icons, combined with an arbitrary 500 KB string inside `properties.description`.
  2. When the victim opens the link, the map renders locked, presenting the content as an authoritative historical map layer.
  3. When clicked, `showCard()` passes the unconstrained `description` string to `host.card()`. The text claims: *"Official site announcement: Security update required at https://malicious-site.example"*.
  4. Readers are deceived because the shared marks blend seamlessly into the site UI without any indicator that they originated from an external URL parameter.
- **Static Site Mitigation:**
  - When `fromLink === true`, display a persistent banner stating *"Viewing shared annotations from link (unverified external content)"*.
  - In `adopt()`, enforce strict character limits on untrusted properties (`title` max 120 chars, `description` max 2000 chars, matching the UI field limits).
  - Prefix card titles with `[User Annotation]` so external text cannot impersonate native historical commentary.

### 6. Medium: Thread Freeze via Feature Array Flooding in `loadText()`

- **Citations:** [L669–705](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L669-L705) (`drawList`), [L715–740](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L715-L740) (`problemWith`), [L743–746](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L743-L746) (`countVerts`), [L770–778](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L770-L778) (`loadText`)

### 7. Medium: Race Condition in `prepLink()` Overwrites Link with Stale Data

- **Citations:** [L707–735](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L707-L735) (`fieldChanged`), [L767–790](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L767-L790) (`styleChanged`), [L849–866](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L849-L866) (`prepLink`), [L898–920](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L898-L920) (`copyLink`)
- **Failure Scenario:**
  1. A user types a title in the input box, pauses 250ms, triggering `schedulePack()`.
  2. `prepLink()` captures `var mine = feats;` and begins asynchronous `pack(slim(collection()))`.
  3. While `pack()` is in flight, the user edits the description. `fieldChanged()` mutates `f.properties.description` *in-place* on the existing feature object inside the same `feats` array.
  4. The user immediately clicks "Copy link" ([L898](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L898)), which calls `prepLink()` again to pack the new state.
  5. The first `pack()` promise resolves. It checks `if (feats !== mine) return;`. Because `feats` was mutated in-place, the array reference is identical (`feats === mine` is `true`).
  6. The older resolution sets `linkCode = code` (stale code) and resets `linkDirty = false`.
  7. When the user copies or shares the URL, the link contains the stale data without the updated description.
- **Static Site Mitigation:**
  Maintain an incremental packing sequence counter (`packSeq++`). Reject / discard any promise resolution where `currentSeq !== packSeq`.

### 8. Medium: Damaged or Truncated Links Silently Discard Restore Affordance

- **Citations:** [L1198–1216](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L1198-L1216) (`fromUrl`)
- **Failure Scenario:**
  1. A user with existing personal annotations receives a shared link that was truncated by an email client.
  2. The user navigates to the URL. `fromUrl()` runs: `shadowed = restore()` correctly finds their 10 saved annotations.
  3. `unpack(code)` rejects because base64 decoding or decompression fails on the truncated bytes.
  4. The rejection handler ([L1211–1215](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L1211-L1215)) executes:
     `shadowed = null; fromLink = false; fold(false); say('That shared link could not be read...', 'bad');`
  5. `shadowed` is wiped to `null`, and `offerRestore()` is never called.
  6. The user sees an empty map with no `#ann-mine` button and no prompt to bring back their 10 annotations.
- **Static Site Mitigation:**
  In the `fromUrl` error catch handler, do not wipe `shadowed` to `null`. Check if `shadowed` contains features and automatically restore them or call `offerRestore()`.

### 10. Low: `unB64()` Parser Rejection on Whitespace or Malformed Length

- **Citations:** [L816–823](file:///Users/kml/.gemini/antigravity-cli/scratch/link-review-input.js#L816-L823) (`unB64`)
- **Failure Scenario:**
  1. A link is shared via email or chat and pasted into the browser address bar with an encoded space `%20` or newline at the end.
  2. `unB64` runs `while (s.length % 4) s += '='`.
  3. If the input string length modulo 4 equals 1 (which can occur if an isolated character or malformed padding was introduced), padding produces a length divisible by 4, but `atob` throws a `DOMException: The string to be decoded is not correctly encoded`.
  4. The link is rejected as corrupted rather than cleaned.
- **Static Site Mitigation:**
  Strip all whitespace prior to decoding: `str = (str || '').trim().replace(/\s+/g, '');`. Check `if (str.length % 4 === 1) return Promise.reject(...)`.
