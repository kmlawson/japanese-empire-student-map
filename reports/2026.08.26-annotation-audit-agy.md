### 1. Work done after opening a shared link is permanently lost on reload
* **Lines**: 217–224, 227–233, 1205–1233
* **Concrete failure scenario**:
  1. A student opens a map via a classmate's shareable link (`?ann=...`).
  2. `fromUrl()` executes, setting `fromLink = true`.
  3. The student clicks the pencil icon to edit (`setLocked(false)`), creates several new marks, polygons, and descriptions over 30 minutes.
  4. `changed()` calls `store()`. Because `fromLink` is `true`, `store()` writes to `ANN_STORE_SHARED` (`jem-annotations-shared-v1`) and leaves `ANN_STORE` untouched. `fromLink` is never reset to `false` during editing.
  5. The student closes the tab and re-opens the map later directly (without the `?ann=` query parameter).
  6. `open()` calls `offerRestore()`, which calls `restore()`. `restore()` only queries `ANN_STORE` (`jem-annotations-v1`).
  7. All work saved to `ANN_STORE_SHARED` is completely ignored and never offered for restoration. If the student ever re-opens the original link URL, `fromUrl()` overwrites `ANN_STORE_SHARED` with the original URL payload. The student's work is permanently lost.

### 2. Returning to own work and pressing Undo silently destroys original work in localStorage
* **Lines**: 1241–1255, 160–178, 217–224
* **Concrete failure scenario**:
  1. A teacher has 10 annotations saved in `ANN_STORE`.
  2. The teacher opens a shared link. Their existing annotations are saved to `shadowed`.
  3. The teacher clicks "Back to my annotations" (`backToMine()`). This takes a snapshot, restores `feats`, sets `fromLink = false`, sets `shadowed = null`, and announces: *"The shared set is in Undo if you want it."*
  4. The teacher presses Ctrl+Z / Cmd+Z (or clicks Undo).
  5. `undo()` pops the shared set into `feats` and calls `changed(true)`.
  6. `changed(true)` calls `store()`. Because `fromLink` was set to `false`, `store()` writes the shared set directly into `ANN_STORE`, permanently overwriting the teacher's original annotations in localStorage.
  7. Because `shadowed` was already cleared, closing the browser tab permanently destroys the teacher's original annotations.

### 3. Missing snapshots on title, description, and style edits causes Undo to wipe out text and revert to old geometry
* **Lines**: 743–764, 868–899, 160–178
* **Concrete failure scenario**:
  1. A user places a point marker (which triggers `snapshot()`).
  2. The user spends 15 minutes typing detailed historical text into Name (`#ann-title`), Short note (`#ann-short`), Description (`#ann-desc`), and adjusts style colors.
  3. `fieldChanged()` and `styleChanged()` modify `f.properties` in place, but neither calls `snapshot()`.
  4. The user makes an editing mistake while not focused in an input (or presses Undo).
  5. `undo()` pops the snapshot from step 1 (15 minutes prior). All titles, descriptions, dates, and styles across all features are instantly wiped out.
  6. Because there is no redo stack, all text typed since the last geometry addition is permanently unrecoverable.

### 4. Editing titles, descriptions, dates, or styles after saving does not re-arm `beforeunload`
* **Lines**: 201–207, 743–764, 868–899, 970–983
* **Concrete failure scenario**:
  1. A user creates 5 annotations and clicks "Save file".
  2. `save()` calls `setDirty(false)`, which removes the `beforeunload` window listener.
  3. The user continues working by updating descriptions, adding dates, and adjusting styles on the saved features.
  4. `fieldChanged()` and `styleChanged()` update `f.properties` and call `store()`, but never call `setDirty(true)`.
  5. The user accidentally closes the browser tab. The browser exits immediately without displaying an unsaved changes warning. If localStorage quota was exceeded or the user was in private browsing, all modifications made after the save are lost.

### 5. Stale form controls leak styles across feature selections and corrupt default attributes
* **Lines**: 766–801, 868–899, 1030–1048
* **Concrete failure scenario**:
  1. A user selects Arrow A, sets its head to "Stopped (bar)" (`#ann-head`) and its bend to 50 (`#ann-curve`).
  2. The user selects Arrow B, which was drawn with default properties (where `jem-arrow-head` and `jem-curve` are `undefined` or stripped by `slim()`).
  3. `syncFields()` checks `if (hd && p['jem-arrow-head'])` and `if (cv && p['jem-curve'] !== undefined)`. Because Arrow B lacks these properties, the form controls are NOT reset to defaults; `#ann-head` stays "Stopped (bar)" and `#ann-curve` stays 50.
  4. The user changes Arrow B's color. `styleChanged()` reads `#ann-head.value` and `#ann-curve.value`, mutating Arrow B into a curved stopped arrow. (The same bug occurs for `#ann-symbol` on point markers and `#ann-fillop` on polygons).

### 6. Touch tap fails to cancel hold timer, leaving drag armed and teleporting marks on subsequent map pans
* **Lines**: 577–599, 607–618, 472–516
* **Concrete failure scenario**:
  1. On a touch device, a user quickly taps a mark (<330ms) to read its description.
  2. `grab()` is called with `coarse = true`, arming `holdTimer` (330ms).
  3. On tap release, the map host triggers `tap()`. `tap()` selects the feature and shows the detail card, but does not call `letGo()`.
  4. 330ms after the initial touch, `holdTimer` fires in the background with no finger touching the screen, executing `beginDrag()` and setting `dragging` to an active object.
  5. The user touches an empty part of the map to pan. The host calls `drag(cx, cy)`.
  6. `drag()` sees `dragging` is active and instantly relocates the previously tapped annotation to the new touch coordinate.

### 7. Right-clicking an arrow's bend handle deletes the entire arrow
* **Lines**: 418, 694–720, 722–731
* **Concrete failure scenario**:
  1. A user draws an arrow and selects it. In `redraw()`, the bend control handle is rendered with metadata `{ i: i, r: 0, v: 2 }`.
  2. The user right-clicks the bend handle expecting to reset or remove the curve.
  3. `rightClick()` invokes `removeVertex(i, 0, 2)`.
  4. In `removeVertex()`, `g.coordinates` for an arrow has length 2 (indices 0 and 1). Because `v = 2` is `>= ring.length`, `removeVertex()` returns `false`.
  5. `rightClick()` receives `false` and falls through to `removeAt(i)`, deleting the entire arrow. (The same bug occurs when right-clicking any vertex of a `MultiPolygon` or `MultiLineString`).

### 8. Clock hides whole-year events mid-year because absent end dates parse to January 1st
* **Lines**: 757–789, 800–812, 815–836
* **Concrete failure scenario**:
  1. A teacher enters an event that occurred throughout 1931: Start: "1931", End: "1931". Another event is added with Start: "Sept 1931".
  2. `parseWhen("1931")` defaults all missing months and days to `1`, returning `19310101` for both the start and end dates.
  3. The clock timeline generates stages `[19310101, 19310901]`.
  4. At stage `19310101` (Jan 1931), the event is visible.
  5. At stage `19310901` (Sept 1931), `inScope()` checks `d > b` (`19310901 > 19310101`) and hides the 1931 event before 1931 has finished.
  6. If an event has Start: "1931-05-01" and End: "1931", Start (`19310501`) > End (`19310101`), making the event permanently invisible during timeline playback.

### 9. Area calculations fail across the 180° Antimeridian
* **Lines**: 352–360, 460–469
* **Concrete failure scenario**:
  1. A user traces an area in the Pacific theatre across the 180° meridian (e.g. Marshall/Gilbert Islands or Aleutians, from +179° to -179°).
  2. In `sphericalArea()`, `(b[0] - a[0])` calculates `-179 - 179 = -358°` instead of `+2°`.
  3. `sphericalArea()` calculates an impossible area covering hundreds of millions of square kilometers.
  4. In `anchorOf()`, longitudes across the meridian are averaged directly (`(179 + -179) / 2 = 0°`), placing the polygon's text label at Greenwich, London instead of the Pacific.

### 11. Stale SVG blur filter cache breaks blurred polygon rendering on SVG reset
* **Lines**: 468–508
* **Concrete failure scenario**:
  1. A user draws a polygon with a blurred boundary. `blurFor()` creates `<filter id="ann-blur-3">` inside `#ann-defs` and caches the DOM node in `blurs[3]`.
  2. The host map resets or re-attaches the SVG root (e.g., during map re-projection or layer toggling).
  3. `redraw()` calls `blurFor(3)`. `blurFor()` finds `blurs[3]` in memory and immediately returns `'ann-blur-3'` without verifying if the filter element exists in the new SVG DOM.
  4. Polygons reference `filter="url(#ann-blur-3)"`, which does not exist in the active SVG `<defs>`, causing blurred polygons to render without blur or fail to display.

### 12. Non-ISO numeric dates silently drop months and days
* **Lines**: 757–789
* **Concrete failure scenario**:
  1. A user types a date formatted as `8/12/1941` or `12/8/1941` into `#ann-start`.
  2. The initial regex `^(\d{3,4})` fails because the year is not first.
  3. In the regex fallback, `mon` is only set if a named month string (`[a-z]{3,}`) matches. Because no text month exists, `mon` remains `null`.
  4. The day parsing condition `else if (mon !== null && day === null && +n <= 31)` is never satisfied.
  5. `parseWhen()` drops the month and day entirely, returning `19410101` (January 1, 1941). The timeline is silently assigned the wrong date.
