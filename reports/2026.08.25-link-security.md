# The shared link: what is actually exposed, and what a serverless site can do

`codex` and `agy` were each given `annotate.js` with a context block saying
plainly what the site is — static, no server, no accounts, no cookies — and
asked about the `?ann=` link specifically. Their raw reports are beside this
one. **Nothing below is relayed unchecked**; each claim is marked with what I
did to test it.

## Confirmed by measurement

### 1. There is no length check on an *incoming* link, and a long one hangs the tab

Every `ANN_URL_MAX` test in the file is on the **outgoing** side — refusing to
*produce* a link over 6,000 characters. `fromUrl()` accepts a code of any
length, and `unpack()` decompresses the whole thing into a string before
`loadText()` looks at it.

**Measured.** One legal feature whose description is 80 million identical
characters compresses to a link of **103,843 characters**. Opening it left the
page with **no message at all after 120 seconds** — not an error, not a
refusal: a hung tab. No page error was raised, so nothing recovers.

Deflate on repetitive text runs to about 1000:1, so the ceiling on damage is
set by how long a URL the reader's browser will follow, which is far more than
this needs.

**What a static site can do.** Refuse an incoming code longer than the same
`ANN_URL_MAX` the map will not exceed when writing one — a link this map could
not have produced is not a link it needs to open. Then decompress *through a
counting stream* and abort past a byte budget, rather than materialising first
and checking after.

### 2. A link that fails to load still reports success

**Measured.** A 200,000-point payload — a 4,828-character link, comfortably
**inside** the 6,000 ceiling — is correctly refused by the 60,000-vertex cap:
nothing is drawn. The map then says *"These annotations came with the link."*

`fromUrl()` does not look at what `loadText()` returned, and writes its own
message over the failure. The reader is told a set arrived and sees an empty
map.

### 3. Copy link republishes every query parameter it was opened with

`linkUrl()` strips only `ann`. Anything else in the address at the time — a
tracking parameter seeded by whoever sent the reader the first link — is copied
into the reader's own link and passed on. Rebuilding from an allowlist of the
map's own parameters fixes it.

## Real, but a product decision rather than a bug

### 4. A crafted link puts an attacker's claims on this map, under this domain

A shared link opens locked with the panel closed, so the only sign that
anything came from outside is a pencil button. Somebody can therefore publish a
`kmlawson.github.io/...` address whose annotations assert whatever they like —
false frontiers, invented events — and it will look like part of the map.

**No serverless site can verify authorship**, and signing does not help: an
attacker recomputes any unsigned digest, and a signing key shipped to the
browser is not a key. What is available is honesty about provenance — a
standing, visible mark that these annotations came from a link and are somebody
else's, rather than a pencil button and a message that scrolls away.

This is the finding I would act on first, and it is the one I least want to
decide alone: it is a judgement about how the map presents itself.

## Raised, and overstated

* **"A short link freezes the tab."** The 200,000-point case — 1.8 MB of JSON
  from 4,828 characters, a 373× expansion — decompressed, parsed and was
  rejected in **0.2 seconds**. Real bombs need a payload far larger than the
  6,000-character ceiling, which is why the missing *inbound* check is the
  finding and the expansion ratio is not.
* **`__proto__` in properties.** `adopt()` copies keys onto a plain object
  literal, so `__proto__` sets the prototype rather than an own property — but
  in a module that only ever reads its own known keys, the reachable damage is
  a broken feature, not an escalation. Worth normalising; not urgent.

## Not yet checked

Undo restoring a shared set over the reader's own store after **Back to mine**;
storage quota exhaustion by a shared set; deep `GeometryCollection` recursion;
and stale packing disclosing a just-deleted note — which I tested once before
and could **not** reproduce, and which is raised again here with a sharper case
(deletion rather than edit) that I have not yet tried.

## What I propose, in order

1. **Refuse an over-long incoming code, and count bytes while decompressing.**
   Small, entirely inside `unpack`/`fromUrl`, and closes the one confirmed way
   to hang a reader's tab.
2. **Make a failed load say so** — honour `loadText`'s return value instead of
   writing over it.
3. **Rebuild the copied link from an allowlist** of the map's own parameters.
4. **Decide together what a shared set should look like**, given that the map
   cannot vouch for it.

Nothing here is changed yet.
