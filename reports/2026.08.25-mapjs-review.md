# map.js — outside review, verified

25 August 2026. Fifteen findings from `codex`, each checked against the code and,
where it could be done, driven in a headless browser and measured. The findings
were reported first and fixed afterwards, on the same day — see **What was
done**, below, and `docs/tasks.md` #129.

**One reviewer, not two.** `agy` returned nothing at all — *"a tool required the
'command' permission that headless mode cannot prompt for, so it was auto-denied"*
— so there is no second opinion here and no place where independent agreement
can be claimed. The raw review is in `2026.08.25-mapjs-review-codex.md`.

Of the fifteen: **nine confirmed** (four of them measured in the browser), **one
true but by design**, **five true-but-trivial or narrow**. None was a
hallucination — the line references were off only by the offset of the copy that
was sent, and every quoted mechanism was in the file.

---

## Ranked by what would actually bite a reader

### 1. Two sets of Chinese provinces on the map at once — CONFIRMED, measured

`loadAdmin()`'s graft inserts its ENP province nodes into every atom
unconditionally (`map.js:5827`) and never asks what `provSource` is. If the ROC
file arrives first, `setProvinceSource('roc')` finds `provSets.enp` still empty,
has nothing to take out, and inserts ROC alongside — then the admin fetch lands
and adds ENP on top.

Measured, four loads out of four, `?layers=` with the ROC bit set:

| | provinces inside `#a-china` |
|---|---|
| ENP only | 21 |
| ROC link | **42** |

Both sets answer `querySelectorAll`, so every sweep over sub-units — the hover
outline, the cluster, the name — sees each boundary twice. Duplicate `Sichuan`,
`Yunnan` and `Gansu` nodes were present at indices 1/2/6 and 23/38/40.

### 2. The ROC provinces are never reprojected — CONFIRMED, measured

`reprojectGraft()` is called from exactly two places (`map.js:5678`, `5843`) —
the fine coastline and the administrative sheet. `loadRoc()` calls neither, and
`reprojectDocument()` only walks nodes attached to the SVG, so a set parked in
`provSets` is skipped.

Measured, same page, Albers, `#a-china`:

| province | ENP copy | ROC copy |
|---|---|---|
| Gansu | x 786, y 565 | **x 548, y 380** |
| Sichuan | x 863, y 753 | **x 693, y 594** |

The ROC boundaries are still at their Mercator coordinates — 238 × 185 map units
adrift, which is most of a province. They snap into place if the reader changes
projection again afterwards, because by then they are attached and
`reprojectDocument()` can see them.

**Both of these are ROC-only, and ROC has no switch.** The radio `#prov-roc` that
`map.js:738` looks for is not in `index.html` — the source came out of the Layers
panel when the period sheet was redrawn, and bit 128 was deliberately kept
working so old links would still mean what they meant. So this is reachable only
by following such a link — but a reader who follows one and then shares their own
view passes the bit on, because `layerCode()` writes it.

### 3. Label nudges are computed and thrown away — CONFIRMED, measured

`placeLabels` moves a colliding label through ten offsets, and on success updates
the local `x`, `y` and `box` and pushes `box` into `placed` (`map.js:2924–2936`).
Nothing writes it back: a label's screen position comes from the `transform`
`rescale()` puts on its `scalables` entry, and that is untouched. `x` and `y` are
dead from the assignment onwards.

Instrumented and caught in the act — Karafuto, one frame, element already visible:

```
drawn top  −32      recorded box top  +5      nudge applied  +37.26
```

So the map both draws the name where it collides *and* reserves the empty space
it was moved to, which can suppress a second name that would have fitted there.
Nine nudges fired in ten wheel steps from the opening view, offsets from 32 to
100 px — Kwantung Leased Territory, Karafuto, Hachijōkojima and the Izu islands.

The comment above the block names Nepal, Sikkim and Bhutan as the case it was
written for. That case has never worked.

### 4. Label DOM grows without bound as fine windows are revisited — CONFIRMED, measured

`dropFine()` (`map.js:5686`) removes a window's island nodes but not the `<text>`
elements or the entries in `labels`, `subLabels` and `scalables`. `gateLabels()`
only hides them, off `L.owner.isConnected`. Coming back re-imports the rings as
*new* elements, so the `subLabelled` WeakSet has never seen them and builds a
second complete set of names.

Measured, names on, alternating Ryukyus ↔ Solomons:

| | `labels` | `<text>` in `#labels` | live `.fine` | `placeLabels` |
|---|---|---|---|---|
| start | 909 | 909 | 0 | 0.26 ms |
| after 1 cycle | 1,899 | 1,899 | 126 / 1,004 | 0.46 ms |
| after 2 | 2,701 | 2,701 | — | 0.56 ms |
| after 3 | 3,503 | 3,503 | — | 0.72 ms |
| after 4 | 4,305 | 4,305 | — | 1.12 ms |

+802 nodes per round trip, monotone, never reclaimed. The live geometry stays
flat, so this is pure accumulation. Worth saying what does *not* leak: zooming in
and out of the *same* window does nothing, because the window is never dropped —
it needs the view to leave the region entirely.

`placeLabels` runs on every pan frame over the whole inventory, which is codex's
finding 5; the two compound. 1.12 ms a frame is not yet jank on this machine, but
it is unbounded and a school laptop is several times slower.

### 5. A pan and a zoom in the same frame lose the rescale permanently — CONFIRMED, measured

`applyView` captures `zoomed` in the closure it hands to `requestAnimationFrame`
(`map.js:2451–2461`). A second call before that frame runs updates `lastScaleW`
but cannot upgrade the pending callback, so `rescale()` and `gateLabels()` are
skipped — and because `lastScaleW` moved, every later pan computes
`zoomed === false` too. Nothing repairs it but another real zoom.

Measured: pointer-drag then a wheel tick in one frame, then a further pan.

```
baseline                     wanted k 2.6415   actual scale(2.6415)
after pan + wheel same frame wanted k 1.6345   actual scale(2.6415)   ← 62% oversize
after a further pan          wanted k 1.6345   actual scale(2.6415)   ← not repaired
```

City dots, their names and the hatch patterns all stay at the wrong screen size.
Synthetic events land in one frame reliably; by hand this needs a trackpad
two-finger scroll during a drag, or the transition frame of a pinch. The
mechanism is real and the "never repairs itself" half is the damaging part.

### 6. The selection outline is not rebuilt after a change of projection — CONFIRMED stale, no visible effect found

The outline is stroked through a mask whose rectangle is sized to the shapes
being outlined (`map.js:4341`). `reprojectDocument()` calls `bumpHi()`, so the
slot key is stale by construction — but the projection radio called
`applyState()` and nothing else, and `redrawHighlight()` was never reached.
Proved by watching the mask across a switch: `mask-2` kept its Mercator numbers
`[91, −11, 1351, 1024]` while China moved to `[717, 565, 529, 521]`.

**A correction to my first pass on this.** I reported "695 map units of the
Soviet Union's outline outside the mask", comparing the mask against the whole
atom's bounding box. That is not what the mask is sized to — it is sized to the
shapes the outline is built from, which is a smaller set — so the number was
meaningless. Going back and comparing what the reader actually sees, by
screenshotting *select-then-switch* against *switch-then-select* for eight
territories: every pair that selected the same country came out byte-identical,
before the fix and after it. The reprojected shape lands inside the old
rectangle in every case I could construct.

So this is a real staleness with no demonstrated symptom. It is fixed anyway —
one call, matching what every other layer switch in the file already does — and
the fix is pixel-neutral, which is the evidence that it breaks nothing rather
than evidence that it was needed.

### 7. Opening the annotation tools leaves the outline behind — CONFIRMED

`makeRoom()` closes the card and sets `selected = null` without calling
`redrawHighlight()`. Measured: select China, press Create — card closed,
`selected` null, and `#highlight .hi-selected` still present and drawn. The
masked outline is the expensive one, and it stays until something else happens
to redraw. `card()` a few lines below has the same shape.

### 8. Switching province source keeps a stale province in the card — CONFIRMED (by reading)

`setProvinceSource` calls `select(selected)` without clearing `lastProv` or
`hotProv` (`map.js:5784`), and `select()` rebuilds the card head from
`lastProv.rec` (`map.js:4671`). The card can go on naming a province whose node
has just been detached. With a mouse the next hover corrects it; on a touch
screen nothing does. ROC-only, so it rides on findings 1 and 2.

### 9. A failed fine-coastline fetch retries forever — CONFIRMED (by reading)

`fineState` documents a `failed` state and the catch sets it to `'none'`
(`map.js:5527`). `syncFine()` runs on every settled movement, so an offline
reader zoomed into Okinawa fires a new request on every pan and wheel, with no
backoff and nothing on screen to say fine detail is unavailable.

### 10. A failed ROC fetch can never be retried — CONFIRMED (by reading)

The mirror image, and the reason both are worth mentioning together.
`loadRoc()`'s catch sets `rocState = 'failed'`; `setProvinceSource` only calls
`loadRoc()` when the state is `'none'` (`map.js:5773`). After a transient
failure, asking for ROC again flips `provSource` and the radio, fetches nothing,
and — since `provSets.roc` is empty — leaves ENP attached. The control says one
thing and the map shows another.

---

## True, but by design

**The whole fine file is parsed and kept.** `fineDoc` holds the complete parsed
document for the life of the visit and grafting is per window (`map.js:5510`).
Codex reads this as a defect; the comment directly above says it is the point —
it is what lets two overlapping windows be added and removed in any order without
leaving the map half-pruned. The saving that was wanted was in what is *live and
drawn*, and that is being had. Not a bug; a trade-off already argued in the file.

---

## True but trivial, or too narrow to act on

- **Level 4 is reachable from a hand-edited link.** `applyLayerCode` yields
  `((bits >> 8) & 3) + 1`, so 1–4; `layerCode()` clamps to 1–3 and saved-state
  validation accepts 1–3. Set both bits and the session runs at level 4, no level
  button reads as on, and the address bar rewrites itself as 3. Real, one line to
  fix, needs somebody to type it.
- **The standalone bootstrap has no error boundary.** The fetch path ends
  `.catch(showLoadError)`; `Promise.resolve(window.JMAP_INLINE_SVG).then(init)`
  does not (`map.js:554`), and `init` dereferences `viewBox` and `#proj` without
  checking. Only bites a damaged single-file build, which is a build we make.
- **Dead code, all three as described.** `terrLabelByEl` is written at
  `map.js:1878` and never read; `lastDouble` is declared at `2489` and neither
  read nor written; the `Object.keys(elById)` loop at `1771` has a body that can
  only `return` from the callback and does nothing at all.

## The order I proposed, at the time of reporting

1. **Fix the nudge** (finding 3). Smallest change with the widest reach — it
   affects every reader with names on, at every zoom, and the code is already
   there and simply not connected. It needs the offset written where `rescale()`
   will apply it, and it needs the map-units/screen-pixels rule applied
   carefully: the nudge is computed in screen pixels and `scalables` are
   positioned in map units.
2. **Stop the label leak** (finding 4). `dropFine` should take out the labels it
   is orphaning, the same way `composeEpoch` filters `scalables`.
3. **Fix the rAF coalescing** (finding 5). Hoist `zoomed` to a module-level flag
   the pending frame reads and clears, rather than one captured per call.
4. **Redraw the highlight after a projection change** (6) and after `makeRoom`
   (7). Two call sites.
5. **Decide about ROC** (1, 2, 8, 10). It has no UI. Either wire it properly —
   reproject on load, respect `provSource` in the admin graft, clear `lastProv`
   on the swap, allow a retry — or drop the code and let bit 128 be ignored. It
   is currently in a state where following an old link produces a visibly wrong
   map, which is worse than either.
6. **Give the fine fetch a failure state** (9) so a bad connection is not a
   request per pan.
7. The trivia can ride along with whatever else touches those lines.

Nothing here is urgent for a reader who does not follow an ROC link, does not
leave and re-enter a fine-coastline region, and does not zoom during a pan. The
nudge is the exception: that one is wrong on every load.

## What was done

All of it, on 25 August 2026, with the measurements repeated afterwards. See
`docs/tasks.md` #129. Two new test scripts guard the work: `tools/test/labels.js`
(19 checks) and `tools/test/provsource.js` (9). Both fail on the code as it was
— five failures and four — and pass on the code as it is.

| finding | what changed |
|---|---|
| nudge discarded | `placeScalable()` is now the one place a scalable's transform is written, and `placeLabels` puts the offset in `sc.nx`/`sc.ny`, in screen pixels |
| widths were guessed | `gateLabels` measures the real width with `getComputedTextLength`, batched after all the writing so it costs one layout |
| labels leaked | `dropLabelsFor()`, called from `dropFine` with the nodes that window is taking out |
| zoom lost in a coalesced frame | `rafZoomed` is a module-level flag, not a closure variable |
| outline left standing | `redrawHighlight()` from the projection radio, from `makeRoom` and from `card` |
| both province sheets drawn | the administrative graft puts its own away when the Republic's is showing, and the swap takes out whatever the atom already carries — China's provinces are in the base map file, which is why `provSets` never held them |
| the Republic's sheet in the wrong projection | `reprojectGraft` on insert, and it can now put nodes back into Mercator as well as out of it |
| ROC could not be retried | `setProvinceSource` starts a fetch from `failed` as well as from `none` |
| stale province in the card | `lastProv`/`hotProv` cleared on the swap |
| fine fetch retried forever | `failed` is a real state now, with one attempt every 30 seconds |
| level 4 | clamped in `applyLayerCode` |
| standalone had no error boundary | `.catch(showLoadError)`, and `init` checks `viewBox` and `#proj` |
| dead code | `terrLabelByEl`, `lastDouble` and the no-op `elById` loop are gone |

Measured after: label overlaps at the opening view and through six wheel steps
went 18/8/2 to 0/0/0 with the same names on screen; the label count across four
Ryukyus–Solomons round trips is flat at 1,211/1,785 instead of climbing to
4,305; a pan and a wheel in one frame leave the markers at the scale the view
asks for, and still do after a further pan; China's atom holds 21 provinces on
every combination of source and projection instead of 42; `gateLabels` costs the
same as before (0.6–2.7 ms shallow, 2.7–3.9 ms over the Solomons). Fourteen map
states were screenshotted before and after: twelve byte-identical, and the two
that differ are the names, which is the point.

Not done: the whole fine file is still parsed and kept, which is the documented
trade-off, and label placement is still a full-inventory pass per frame — worth
looking at separately now that the pile no longer grows.
