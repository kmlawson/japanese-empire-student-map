## Critical

1. **“Back to my annotations” followed by Undo destroys the reader’s own stored set.** `backToMine()` switches `fromLink` to false, snapshots the shared set, restores the reader’s set, and explicitly tells them the shared set is available through Undo. Undo then restores the shared snapshot, but because `fromLink` remains false, `changed()` writes that shared set over `jem-annotations-v1`. The reader’s set is no longer in memory, storage, or Undo. Scenario: open a classmate’s link → “Back to my annotations” → Undo as invited → reload; the classmate’s work is now stored as the reader’s, and the reader’s work is gone. [annotate.js:125](annotate.js:125), [annotate.js:198](annotate.js:198), [annotate.js:3140](annotate.js:3140)

2. **Loading a file in replacement mode silently overwrites unsaved work and its localStorage backup.** `loadText()` snapshots the existing set only for in-session Undo, replaces `feats`, immediately stores the new set, and then marks it clean. There is no confirmation even when the current set is dirty. Scenario: draw an unsaved assignment → use the main “Load annotations…” action → choose another file → close or reload before pressing Undo; both the live work and browser backup have been replaced, and the unload warning was disarmed. [annotate.js:2386](annotate.js:2386), [annotate.js:2412](annotate.js:2412), [annotate.js:2422](annotate.js:2422), [map.js:6934](/Users/kml/shell/interactive-japan-map/map.js:6934)

3. **Text, date, and style edits to a shared set can be lost with no unload warning.** Opening a URL explicitly clears `dirty`; `fieldChanged()` and `styleChanged()` mutate and store data but never call `setDirty(true)`. Shared edits are stored only under the shared key, which is not offered for restoration on an ordinary visit, and reopening the original link overwrites them. Scenario: open a teacher’s link → unlock it → change only a title, description, date, or colour → reload; there is no warning and the edit disappears. [annotate.js:1935](annotate.js:1935), [annotate.js:2207](annotate.js:2207), [annotate.js:3099](annotate.js:3099)

## High

4. **Failure of the only automatic backup is deliberately hidden.** Every `localStorage` exception—quota exhaustion, disabled storage, private-mode restrictions—is swallowed without telling the reader. Accepted data can approach 6 MB before JSON/storage overhead, already around or beyond common per-origin quotas. Scenario: a student builds a large set, storage fills, and the tab or browser crashes; the UI gave no indication that none of the recent work was backed up. [annotate.js:198](annotate.js:198), [annotate.js:206](annotate.js:206)

5. **Two tabs silently overwrite each other.** All ordinary work uses one unversioned localStorage key, and every edit writes the complete set. There is no storage-event handling, revision check, or conflict copy. Scenario: a teacher opens the map in two tabs, works on Set A in one and Set B in the other; whichever tab makes the last edit replaces the only browser backup for the other set. [annotate.js:58](annotate.js:58), [annotate.js:198](annotate.js:198)

6. **Asynchronous packing can publish a stale link while claiming success.** `prepLink()` guards completion using `feats !== mine`, but nearly all edits mutate the existing array or feature objects in place. An older compression can therefore finish after a newer edit, set `linkDirty` to false, and suppress the scheduled repack. Scenario: pause after typing so compression begins → change the description or move a point while it runs → press Copy link; the copied URL can contain the old text or geometry while the UI says anyone opening it will see the current annotations. [annotate.js:2580](annotate.js:2580), [annotate.js:2616](annotate.js:2616), [annotate.js:2692](annotate.js:2692)

7. **Unfinished lines and areas are discarded without confirmation or Undo.** Changing tools calls `cancelDraft()`, while folding or locking the panel puts the tool away and consequently cancels the draft. Draft vertices are never snapshotted or stored. Scenario: trace twenty polygon corners, then accidentally tap another tool, fold the phone sheet, or press Lock; the entire trace vanishes permanently. [annotate.js:1145](annotate.js:1145), [annotate.js:1175](annotate.js:1175), [annotate.js:2889](annotate.js:2889), [annotate.js:3041](annotate.js:3041)

8. **Undo does not track text or style edits and instead undoes an unrelated structural operation.** Field and style handlers make no snapshot. Scenario: draw a second mark, write its title and description, then press Undo expecting the edit to be reverted; Undo restores the snapshot from before the second mark was created, deleting the entire mark, with no Redo. [annotate.js:120](annotate.js:120), [annotate.js:1935](annotate.js:1935), [annotate.js:2207](annotate.js:2207)

9. **A decoded but invalid shared link is reported as successfully loaded.** `loadText()` returns false after validation errors, but `fromUrl()` ignores that return value, locks the empty/old set, clears dirty state, and replaces the error message with “These annotations came with the link.” Scenario: a validly compressed link contains `{}` or an invalid GeoJSON structure; the page first rejects it internally and then tells the reader it arrived. [annotate.js:2388](annotate.js:2388), [annotate.js:3099](annotate.js:3099)

10. **The stated vertex limit can still create enough DOM to freeze a phone.** A file with exactly 60,000 vertices is accepted, its first feature is selected, and `redraw()` creates an SVG marker/handle—several nodes plus a scalable entry—for every selected vertex. Scenario: load one 60,000-point LineString or Polygon; the initial render attempts tens or hundreds of thousands of SVG nodes and can hang before the reader can deselect it. [annotate.js:46](annotate.js:46), [annotate.js:882](annotate.js:882), [annotate.js:2404](annotate.js:2404), [annotate.js:2420](annotate.js:2420)

11. **Clock rendering is accidentally quadratic, and ordinary typing repeatedly rebuilds and serializes everything.** During a clock redraw, every feature calls `inScope()`, which recalculates and sorts all stages. Every input event also rebuilds the full list, rebuilds all SVG, recalculates the clock, and synchronously JSON-stringifies the complete set into storage. Scenario: type a description with hundreds of dated marks; each keystroke can cause a visible stall, and clock playback repeats an all-features sort once per feature per frame. [annotate.js:797](annotate.js:797), [annotate.js:1746](annotate.js:1746), [annotate.js:1935](annotate.js:1935), [annotate.js:2035](annotate.js:2035), [annotate.js:2056](annotate.js:2056)

12. **GeometryCollections are accepted and then drawn as polygons.** `kindOf()` defaults every unrecognized geometry type to polygon, while `ringsOf()` flattens a GeometryCollection’s points, lines, and polygons together. Scenario: load a valid GeometryCollection containing a point and a line; the point disappears, the line is forcibly closed and filled, and its measurement is reported as area. [annotate.js:297](annotate.js:297), [annotate.js:372](annotate.js:372), [annotate.js:850](annotate.js:850), [annotate.js:2276](annotate.js:2276)

13. **Polygon holes and MultiPolygon holes are rendered and measured backwards.** Rings are flattened and drawn as separate filled paths, so inner rings are filled rather than cut out. Area calculation takes the absolute area of every ring and adds them, so holes increase the reported area. Scenario: import a donut-shaped territory; the lake/hole is painted as territory and counted twice rather than subtracted. [annotate.js:326](annotate.js:326), [annotate.js:336](annotate.js:336), [annotate.js:372](annotate.js:372), [annotate.js:850](annotate.js:850)

14. **Copy link is false advertising on `file://` pages.** When `location.origin` is `"null"`, `linkUrl()` emits only the local pathname, with no scheme or host, yet `copyLink()` says anyone opening it will see the annotations. Scenario: open the standalone map from disk and copy a link; the clipboard contains something like `/Users/teacher/map.html?ann=…`, which an emailed recipient cannot open as the map. [annotate.js:2681](annotate.js:2681), [annotate.js:2707](annotate.js:2707)

## Medium

15. **Date validation silently invents dates and accepts impossible intervals.** Numeric month/day values outside range are changed to January/1 rather than rejected; impossible days such as 31 February pass; and start-after-end is not checked. Scenario: enter `1941-13-20` and it becomes 20 January internally, or enter start `1942` and end `1941` and the mark is hidden at every clock stage. [annotate.js:1947](annotate.js:1947), [annotate.js:1975](annotate.js:1975), [annotate.js:1996](annotate.js:1996), [annotate.js:2056](annotate.js:2056)

16. **An end date does not produce the advertised disappearance at that stage.** `stages()` includes end dates as dates when the map changes, but `inScope()` keeps a feature visible when the current date equals its end. If that is the final stage, the feature never disappears at all. Scenario: a mark starts in 1931 and ends in 1945; stepping to the 1945 “end” stage still shows it, and there is no later stage. [annotate.js:2026](annotate.js:2026), [annotate.js:2035](annotate.js:2035), [annotate.js:2063](annotate.js:2063)

17. **Coordinate validation accepts non-numbers and can later crash link preparation.** Global `isFinite()` coerces `null`, booleans, empty strings, and numeric strings, so they pass `ok2()`. `slimCoords()` assumes anything whose first member is not a number is another array. Scenario: load `coordinates: [null, null]` or `["139","35"]`; it passes validation, may draw in the wrong place, and the delayed link pack throws while recursing into a non-array. [annotate.js:920](annotate.js:920), [annotate.js:2293](annotate.js:2293), [annotate.js:2531](annotate.js:2531)

18. **Null and empty geometries can be reported as successfully loaded invisible features.** A standalone Feature with `geometry: null` passes validation and is retained by `toFeatures()`; an empty GeometryCollection passes because `every()` on an empty array is true. Scenario: load either as a replacement for existing work; the old set is overwritten and the status reports one loaded feature, but there is no mark on the map. [annotate.js:2269](annotate.js:2269), [annotate.js:2278](annotate.js:2278), [annotate.js:2308](annotate.js:2308), [annotate.js:2424](annotate.js:2424)

19. **Concurrent file reads have no sequencing or cancellation.** Each `FileReader.onload` unconditionally applies its captured load operation, regardless of later selections or edits. Scenario: start loading a large file, then select another or draw while the first read is pending; whichever callback finishes last can unexpectedly replace or merge into the newer state. [annotate.js:2434](annotate.js:2434)

20. **Import followed by save silently strips valid GeoJSON metadata.** `adopt()` reconstructs each Feature using only `type`, `geometry`, and `properties`, dropping standard `id`, Feature `bbox`, and foreign members; `collection()` replaces collection-level properties and metadata. This contradicts the claim that the archival file keeps whatever was supplied. Scenario: import a QGIS-produced file whose feature IDs are used to correlate records, add one annotation, and save; all IDs and collection metadata are gone. [annotate.js:2320](annotate.js:2320), [annotate.js:2450](annotate.js:2450), [annotate.js:2513](annotate.js:2513)

21. **Visible edit handles are offered for geometries the drag/delete code cannot edit.** Rendering creates handles for MultiLineString and MultiPolygon rings, but dragging and vertex deletion only support Point, LineString, MultiPoint, and Polygon. Scenario: load a MultiPolygon, select it, and drag or right-click a displayed corner; the apparently interactive handle does nothing. [annotate.js:882](annotate.js:882), [annotate.js:1703](annotate.js:1703), [annotate.js:1817](annotate.js:1817)
