## Findings

1. **High — Alternative province sets are inserted in the wrong projection.** `reprojectDocument()` only processes nodes currently attached to the SVG; detached province sets are skipped. `setProvinceSource()` later inserts those detached nodes without calling `reprojectGraft()`, while the administrative loader explicitly does call it. Scenario: load both province sources, display ROC, switch to Albers, then switch back to ENP. The reinserted ENP boundaries remain in Mercator coordinates and appear displaced from China. Loading ROC for the first time while already using an equal-area projection has the same result. [map-review-input.js:1066](map.js:1066), [map-review-input.js:5770](map.js:5770), [map-review-input.js:5803](map.js:5803), [map-review-input.js:5843](map.js:5843)

2. **High — The two province fetches have a race that can display both datasets simultaneously.** A shared link can start the administrative and ROC requests together. If ROC finishes first, it is inserted correctly; when the administrative request finishes, its graft unconditionally appends ENP paths and never re-enforces `provSource`. The map then contains two overlapping sets of borders, both participating in hit-testing, labels, and outlines. The result depends purely on network timing. [map-review-input.js:733](map.js:733), [map-review-input.js:737](map.js:737), [map-review-input.js:5811](map.js:5811), [map-review-input.js:5827](map.js:5827)

3. **High — Collision “nudges” are calculated but never applied to the label.** When a collision is found, the code changes only local `x`, `y`, and `box` variables, then makes the label visible. It never updates the label’s transform, which remains at the original position set by `rescale()`. Scenario: Nepal collides with a neighbouring label. The placer reserves a supposedly free offset position but renders Nepal at the original collision, producing overlapping text and potentially suppressing another label at the unused reserved position. [map-review-input.js:2561](map.js:2561), [map-review-input.js:2924](map.js:2924), [map-review-input.js:2936](map.js:2936)

4. **High — Revisiting fine-coastline regions leaks label DOM nodes and array entries indefinitely.** Dropping a fine window removes its island shapes but not the corresponding `<text>` elements or entries in `labels`, `subLabels`, and `scalables`. `gateLabels()` merely hides them. Revisiting imports fresh island nodes; the `WeakSet` sees them as new and creates another complete set of labels. Scenario: with names enabled, alternate repeatedly between the Ryukyus and Solomons at deep zoom. Every cycle permanently increases DOM size and makes every later rescale and label pass slower. [map-review-input.js:2664](map.js:2664), [map-review-input.js:2695](map.js:2695), [map-review-input.js:2766](map.js:2766), [map-review-input.js:5685](map.js:5685)

5. **Medium — Label placement is an expensive full-map operation on every pan frame.** Every `applyView()` frame runs `placeLabels()`. That loops over all labels, performs up to eleven linear collision scans per visible candidate, writes display styles, and reads several panel rectangles. Once administrative labels exist, the file itself says there are roughly 1,300 of them. Scenario: enable names, zoom into province-label range, then drag continuously on a school laptop. Each frame processes the entire label inventory rather than the labels near the viewport, causing avoidable jank; finding 4 makes this degrade further over time. [map-review-input.js:2453](map.js:2453), [map-review-input.js:2600](map.js:2600), [map-review-input.js:2721](map.js:2721), [map-review-input.js:2864](map.js:2864)

6. **Medium — A failed fine-coastline request is silently retried after every subsequent settled movement.** Although `fineState` documents a `failed` state, the catch handler resets it to `none`. Every later pan or wheel settle calls `syncFine()`, which starts another fetch. Scenario: the fine SVG is missing or the laptop is offline while zoomed into Okinawa. Each movement generates another failing network request, with no backoff and no indication that fine detail is unavailable. [map-review-input.js:5376](map.js:5376), [map-review-input.js:5511](map.js:5511), [map-review-input.js:5527](map.js:5527), [map-review-input.js:5727](map.js:5727)

7. **Medium — ROC loading has the opposite error: a transient failure can never be retried.** Failure sets `rocState = 'failed'`, but selecting ROC calls `loadRoc()` only when the state is `none`. Scenario: the first ROC request fails briefly, the fallback selects ENP, and the connection recovers. Selecting ROC again changes `provSource` and the radio state but launches no request; because no ROC nodes exist, `setProvinceSource()` leaves ENP attached. The control says ROC while the map still shows ENP. [map-review-input.js:5770](map.js:5770), [map-review-input.js:5778](map.js:5778), [map-review-input.js:5814](map.js:5814)

8. **Medium — RAF coalescing can permanently discard a zoom rescale.** The `zoomed` flag belongs to the first `applyView()` call that schedules the frame. Later calls before that frame update `lastScaleW` but cannot upgrade the pending callback. Scenario: a one-finger pan schedules a non-zoom frame, then a second finger starts a pinch before the frame runs. The pinch changes the view width and records it in `lastScaleW`, but the callback still skips `rescale()` and `gateLabels()`. Markers and labels remain at the wrong screen scale until another actual zoom occurs; plain panning will not repair them. [map-review-input.js:2451](map.js:2451), [map-review-input.js:2453](map.js:2453), [map-review-input.js:3268](map.js:3268)

9. **Medium — Switching province source preserves a stale province selection and card.** The swap removes one set of nodes, then calls `select(selected)` without clearing `lastProv` or `hotProv`. `select()` explicitly rebuilds the card from `lastProv`. Scenario: select an ENP province, then choose ROC. The country remains selected, but the card can continue naming and describing the removed ENP province, while highlight code is handed detached old province nodes. [map-review-input.js:4047](map.js:4047), [map-review-input.js:4671](map.js:4671), [map-review-input.js:5774](map.js:5774), [map-review-input.js:5784](map.js:5784)

10. **Medium — “Per-window” fine loading still parses and retains the entire fine map.** The first qualifying zoom fetches and parses the complete fine SVG into `fineDoc`, retains that entire DOM permanently, and imports a second live copy of the current window. Scenario: zoom only into Japan on a low-memory laptop. The browser still parses and keeps all Pacific windows—including the very large island sets mentioned elsewhere in the file—then duplicates Japan’s live nodes. Grafting is per window, but the expensive parsing and base memory are not. [map-review-input.js:5369](map.js:5369), [map-review-input.js:5377](map.js:5377), [map-review-input.js:5515](map.js:5515), [map-review-input.js:5673](map.js:5673)

11. **Medium — Projection changes invalidate highlight slots but do not redraw them.** Reprojection moves path geometry but not the mask-region rectangles created for highlights. `applyState()` bumps `hiGen`, acknowledging that the cached outlines are stale, but never calls `redrawHighlight()`. Scenario: select India and change from Mercator to Albers on a touch device. The standing selection continues using its old mask bounds and can be clipped or otherwise disagree with the newly projected country until another action happens to redraw the highlight. [map-review-input.js:1066](map.js:1066), [map-review-input.js:4331](map.js:4331), [map-review-input.js:4855](map.js:4855), [map-review-input.js:4874](map.js:4874)

12. **Low — The standalone bootstrap lacks the fetched build’s error boundary.** The fetched path catches exceptions thrown by `init()` and shows the load error; the inline path has no catch. `init()` dereferences both `viewBox` and `#proj` without validation. Scenario: a damaged or mismatched standalone build has a missing `viewBox` or projection metadata. The ordinary build displays an error, while the standalone build produces an unhandled promise rejection and leaves the page broken without guidance. [map-review-input.js:553](map.js:553), [map-review-input.js:556](map.js:556), [map-review-input.js:587](map.js:587), [map-review-input.js:591](map.js:591)

13. **Low — Opening annotation tools clears selection state but leaves the selection outline onscreen.** `makeRoom()` removes the `.sel` marker and sets `selected = null`, but does not call `redrawHighlight()` or drop the selected highlight slot. Scenario: select China, then open the annotation tools. The detail card closes and internal selection state says nothing is selected, but the expensive masked China outline remains visibly selected until another highlight-changing action occurs. [map-review-input.js:4560](map.js:4560), [map-review-input.js:4611](map.js:4611), [map-review-input.js:6474](map.js:6474)

14. **Low — Layer-code validation admits an impossible detail level.** The two level bits decode to values 1–4, although the UI and persisted-state validation allow only 1–3. Scenario: follow a malformed or hand-edited link with both level bits set. Runtime uses level 4, no level button is active, and `layerCode()` rewrites the URL as level 3 while the current session remains level 4. The address, controls, and actual filtering disagree. [map-review-input.js:206](map.js:206), [map-review-input.js:2110](map.js:2110), [map-review-input.js:2150](map.js:2150), [map-review-input.js:6414](map.js:6414)

15. **Low — There is confirmed dead lifecycle code.** `terrLabelByEl` is written but never read, `lastDouble` is never read or written after initialization, and the `Object.keys(elById)` loop has no side effects at all. Scenario: every epoch composition executes the meaningless `elById` scan, while removed territory-label entries remain referenced in the write-only map. The immediate cost is small, but this is exactly the kind of fake cleanup logic that misleads later maintenance of already-fragile state lifecycles. [map-review-input.js:199](map.js:199), [map-review-input.js:1771](map.js:1771), [map-review-input.js:1878](map.js:1878), [map-review-input.js:2489](map.js:2489)
