### 1. Polygons with `pointer-events: all` intercept pointer clicks and block drawing/placement inside their area
* **Lines**: [974–979](file:///annotate.js#L974-L979), [981–997](file:///annotate.js#L981-L997), [2284](file:///annotate.js#L2284)
* **Severity**: Critical / High
* **Concrete Failure Scenario**:
  1. A user draws or imports a polygon covering an area on the map (e.g., a region, sea boundary, or island).
  2. The user arms the "Point", "Line", "Arrow", or "Polygon" tool and clicks inside that polygon to place a mark or corner.
  3. CSS line 2284 sets `#annotations .ann-shape { pointer-events: all; }`. The click event hits the polygon's SVG `<path>` element rather than the map beneath it.
  4. In `tap()` (lines 988–997), `featUnder(target)` matches the polygon and returns its index `hit >= 0`. `tap()` selects the polygon and returns `true` immediately without adding the coordinate to `draft` or placing a point.
  5. **Result**: It is impossible to place points, lines, arrows, or other polygons anywhere inside an existing polygon's boundary.

### 2. State desynchronization in `fromUrl` overwrites local storage, loses imported files, and traps shared state
* **Lines**: [153–160](file:///annotate.js#L153-L160), [1660–1668](file:///annotate.js#L1660-L1668), [2576–2602](file:///annotate.js#L2576-L2602), [2614–2628](file:///annotate.js#L2614-L2628), [2630–2646](file:///annotate.js#L2630-L2646)
* **Severity**: Critical / High
* **Concrete Failure Scenarios**:
  * **Shared link overwriting clean local storage**: A reader with no prior annotations opens a shared link (`fromUrl`). `restore()` returns `null`, so `shadowed` remains `null`. `loadText()` calls `changed()` $\rightarrow$ `store()`. `store()` checks `shadowed ? ANN_STORE_SHARED : ANN_STORE` and writes the shared set into `ANN_STORE`. When the reader returns to the site later without the link, `offerRestore()` treats the classmate's annotations as the user's own saved work.
  * **File loss on shared view**: A user viewing a shared link (`shadowed` holds their work) clicks "Add file..." and loads a local GeoJSON. `loadText()` writes the merged dataset to `ANN_STORE_SHARED`. When the user clicks "Back to my annotations" (`backToMine`), `shadowed.f` overwrites `feats` and deletes `ANN_STORE_SHARED`, permanently destroying the imported GeoJSON file without warning or snapshot.
  * **Orphaned shared state**: If a user edits a shared link and leaves the page without clicking "Back to my annotations", the edits are stored in `ANN_STORE_SHARED`. Normal app loads only read `ANN_STORE`, leaving `ANN_STORE_SHARED` stranded in `localStorage` indefinitely.

### 3. Silent data loss when dataset size exceeds browser `localStorage` quota
* **Lines**: [45](file:///annotate.js#L45), [153–160](file:///annotate.js#L153-L160)
* **Severity**: High
* **Concrete Failure Scenario**:
  1. The editor allows importing files up to 6 MB (`ANN_MAX_BYTES = 6 * 1024 * 1024`).
  2. Standard browser `localStorage` quotas are capped at 5 MB per origin (shared across all keys and stored as UTF-16 in some engines).
  3. A user loads a 3.5 MB GeoJSON file and adds several annotations.
  4. On every change, `store()` calls `localStorage.setItem()`, which throws `QuotaExceededError`.
  5. The `catch (err)` block on line 159 silently swallows the error without notifying the user or marking the file state.
  6. **Result**: The user assumes their work is auto-saving. On browser refresh or tab close, all created annotations and edits are lost.

### 11. Coordinate calculations fail across the 180th meridian (Antimeridian)

* **Severity**: Medium
* **Concrete Failure Scenarios**:
  * **Spherical area calculation**: For a polygon spanning across 180° longitude in the Pacific (e.g., longitudes $179^\circ\text{E}$ and $-179^\circ\text{W}$), `(b[0] - a[0])` calculates $-358^\circ$ rather than $+2^\circ$. `sphericalArea()` calculates an erroneous area covering most of the Earth's surface.
